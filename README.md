# Org Structure Studio

Web application (ไฟล์เดียว `index.html`) สำหรับออกแบบ จัดเก็บ และเปรียบเทียบโครงสร้างองค์กรของกลุ่มบริษัท
PCC, PDE, PPP, SBP, PCE, PBI (เดิม PSL), PEM, PEMC, PSP

> สถานะ: **Prototype** — โครงสร้างจริงของทั้ง 9 บริษัทนำเข้าจาก `Organization_Current_2026-2027.xlsx` (1 แท็บต่อ 1 บริษัท)
> เก็บไว้ใน `data/org-structure.json` เป็นเวอร์ชัน Active ของแต่ละบริษัท ถ้าเปิดหน้าเว็บโดยไม่มีไฟล์นี้ จะแสดงข้อมูลตัวอย่างแทน

## ความสามารถหลัก

| ความต้องการ | สิ่งที่มีใน Prototype |
| --- | --- |
| 1. เก็บ Inactive Version อันเก่า | เมื่อ Publish Draft เป็น Active ระบบย้าย Active เดิมเป็น **Inactive** อัตโนมัติ พร้อมวันสิ้นสุด (ก่อนวันมีผล 1 วัน) เปิดดูย้อนหลัง เปรียบเทียบ และสร้าง Draft ใหม่จากเวอร์ชันเก่าได้ |
| 2. เก็บ Draft Version | สร้าง Draft ได้หลายฉบับต่อบริษัท (คัดลอกจากเวอร์ชันเดิม / แม่แบบมาตรฐาน / แม่แบบ Platform Organization / โครงเปล่า) |
| 3. แก้ไขบนหน้าเว็บ | คลิกเลือก ดับเบิลคลิกเปลี่ยนชื่อ ลากวางเพื่อย้ายสังกัด แก้รายละเอียดที่แผงขวา แท็บ “รายการ” พิมพ์โครงสร้างแบบ outline ได้เร็ว มี Undo/Redo |
| 4. เครื่องมือสร้างโครงสร้างตามเอกสาร | แผนผังแบบลำดับชั้น (คณะกรรมการ › ผู้บริหาร › สายงาน › ฝ่าย › แผนก) หน่วยงานขึ้นตรง (Staff) วางด้านข้าง และ **สร้างจากข้อความ** วางรายชื่อหน่วยงานจาก Word / PowerPoint / PDF / Excel แล้วระบบแปลงเป็นแผนผัง |
| 5. Login ด้วย GitHub Token | ผู้มีสิทธิ์แก้ไขเข้าสู่ระบบด้วย Fine-grained Personal Access Token ทุกครั้งที่กด “บันทึก” จะเป็น commit ไปที่ `data/org-structure.json` ผู้ไม่ได้เข้าสู่ระบบดูได้อย่างเดียว |

ความสามารถเสริมที่สอดคล้องกับการเปลี่ยนผ่านสู่ Agentic AI Organization:

- ประเภทหน่วยงาน **AI Agent** (พร้อมผู้ดูแล human-in-the-loop) **แพลตฟอร์ม** และ **พันธมิตร (Ecosystem)**
- ระบุรูปแบบองค์กรของแต่ละเวอร์ชัน: Industrial → Platform → Ecosystem
- ตัวชี้วัดโครงสร้าง: จำนวนหน่วยงาน อัตรากำลัง ชั้นการบังคับบัญชา Span of control จำนวน AI Agent
- เปรียบเทียบสองเวอร์ชัน: หน่วยงานใหม่ / ยุบ / ย้ายสังกัด / เปลี่ยนชื่อ และผลต่างอัตรากำลัง
- Export เป็น PNG, CSV (เปิดใน Excel ภาษาไทยได้), JSON
- **พิมพ์ / PDF สำหรับลงนามอนุมัติ** (Export › “พิมพ์ / PDF สำหรับลงนามอนุมัติ”): ผังทั้งแผ่นย่อให้พอดี **A3 แนวนอน 1 หน้า** (เลือก A4 ได้)
  มีแถบข้อมูลเอกสาร (บริษัท เวอร์ชัน สถานะ วันที่มีผล) และ **ช่องลงนาม** ผู้เสนอ / ผู้ตรวจสอบ / ผู้อนุมัติ (แก้ชื่อตำแหน่ง ชื่อ-สกุลได้ ระบบจำไว้ต่อบริษัท)
  ถ้าตารางท้ายผังมีช่อง OFFER / VERIFIED / APPROVED อยู่แล้ว ระบบไม่เพิ่มช่องลงนามซ้ำ (เปิดเองได้) ในหน้าต่างพิมพ์เลือก “บันทึกเป็น PDF”
- ซ่อน / แสดงแผงซ้าย (รายการเวอร์ชัน) และแผงขวา (รายละเอียด) ได้แยกกันด้วยปุ่มที่ปลายแถบเครื่องมือ หรือกด `[` / `]` เพื่อให้แผนผังกว้างเต็มจอ ระบบจำค่าไว้ในเบราว์เซอร์

## เปิดใช้งาน

**ทดลองในเครื่อง:** ดับเบิลคลิก `index.html` ได้เลย (ใช้ข้อมูลตัวอย่าง แก้ไขได้ในเบราว์เซอร์)

**ใช้งานจริงผ่าน GitHub Pages:**

1. Repository › Settings › Pages
2. Source: *Deploy from a branch* › Branch `main` / `(root)` › Save
3. เปิด `https://<owner>.github.io/<repo>/`

> หมายเหตุ: GitHub Pages ของ repository ส่วนตัวต้องใช้แพ็กเกจ GitHub แบบเสียเงิน และไฟล์บน Pages เปิดดูได้ตาม URL
> ถ้าโครงสร้างองค์กรเป็นข้อมูลภายใน ให้ตั้ง Pages เป็น private (GitHub Enterprise) หรือเปิดไฟล์จากเครื่องแทน

## สิทธิ์การแก้ไข (GitHub Token)

1. เปิด GitHub › Settings › Developer settings › **Fine-grained tokens** › Generate new token
2. Repository access: **Only select repositories** › เลือก repository นี้
3. Repository permissions › **Contents: Read and write**
4. คัดลอก Token ไปวางในหน้า “เข้าสู่ระบบ”

Token เก็บใน sessionStorage ของเบราว์เซอร์ (หายเมื่อปิดแท็บ) เว้นแต่เลือก “จดจำในเบราว์เซอร์นี้”
และส่งไปที่ `api.github.com` เท่านั้น ผู้ที่จะแก้ไขต้องเป็น collaborator ที่มีสิทธิ์ write ใน repository

## กำลังคน (Workforce) และวางแผนกำลังคน (Workforce Planning)

แต่ละบริษัทมี 3 หน้า (แถบใต้ชื่อเวอร์ชัน) โดยเลือกเวอร์ชันที่แผงซ้ายได้ทั้ง Active และ Draft

| หน้า | ใช้ทำอะไร |
| --- | --- |
| **โครงสร้างองค์กร** | หน้าหลักเดิม: ปรับแก้โครงสร้าง ประกาศ (Publish) และเก็บเวอร์ชัน Active / Draft / Inactive |
| **กำลังคน** | **ผังองค์กรชุดเดียวกับหน้าโครงสร้าง** (สี/ตำแหน่งกล่องตาม Excel, อ่านอย่างเดียว) ทุกกล่องมีป้าย **หัวหน้าหน่วย · จำนวนคนในกล่องนั้น** (ไม่รวมหน่วยย่อย · สีบอกขาด-เกินเทียบแผน) **คลิกกล่องเพื่อ Drill Down**: ผังซูมไปที่สายงานนั้น หน่วยอื่นจางลง แผงขวาแสดงหัวหน้าหน่วย (ตำแหน่ง ระดับ การศึกษา) ตัวเลขของกล่องและทั้งสายงาน หน่วยย่อยพร้อมหัวหน้าของแต่ละหน่วย และรายชื่อ (เฉพาะกล่องนี้ หรือทั้งสายงานแยกตามกล่อง) แถบลำดับบนผังใช้ย้อนกลับขึ้นไป มีมุมมอง “ตาราง” ให้เลือก ค้นหาและ Export CSV ได้ |
| **วางแผนกำลังคน** | **ผังองค์กร** (ค่าเริ่มต้น) ทุกกล่องมีป้าย **คนจริง/แผน** สีบอกขาด-เกิน และป้าย **“สรรหา N”** สีตามขั้นตอน (เทา วางแผน · น้ำเงิน รับสมัคร · ม่วง สัมภาษณ์ · ส้ม เสนองาน · เขียว รอเริ่มงาน · ขอบแดง = เลยกำหนดได้ตัว) ปุ่ม “เฉพาะกล่องที่กำลังสรรหา” ทำให้กล่องอื่นจางลง คลิกกล่องเพื่อดูแผนกับคนจริง ส่วนต่าง จำนวนที่กำลังสรรหา และ “เมื่อสรรหาครบ” แล้ว **เปิด / แก้ / ปิดการสรรหา** ได้ (ตำแหน่ง จำนวน สถานะ เหตุผล วันที่เปิด กำหนดได้ตัว ผู้รับผิดชอบ หมายเหตุ) มุมมอง **ตาราง**: อัตรากำลังตามแผน คนจริง ส่วนต่าง รวมทั้งสาย เทียบแผนใน Active รายการการสรรหา และ Export CSV แก้แผนได้ใน Draft (เป็นส่วนหนึ่งของเวอร์ชัน แล้ว Publish พร้อมโครงสร้าง) ส่วนการสรรหาบันทึกได้ทุกเวอร์ชันและเก็บในไฟล์กำลังคนแบบเข้ารหัส (ไม่เก็บข้อมูลผู้สมัคร) |

- **ข้อมูลพนักงาน** นำเข้าจากไฟล์ Excel ของระบบ HR (รูปแบบ `Employee_workforce.xlsx`: Employee Code, Company Code,
  Structure Unit Code, Structure1–6 (Alt) ฯลฯ) ผ่านปุ่ม “นำเข้าไฟล์พนักงาน” อ่านไฟล์ในเบราว์เซอร์
- **เก็บเฉพาะคอลัมน์ที่จำเป็น** รหัส ชื่อ-สกุล ตำแหน่ง ระดับ กลุ่ม ประเภทการจ้าง วันเริ่มงาน ปีที่เกษียณ สถานที่ทำงาน หน่วยงาน
  Structure Owner และการศึกษา (วุฒิ ปริญญา สาขา สถาบัน) — **ไม่เก็บ** วันเกิด อายุ เพศ
- **หัวหน้าหน่วย** ของแต่ละกล่อง (เฉพาะคนในกล่องนั้น ไม่ดึงคนจากหน่วยย่อยขึ้นมา) = คนที่ระบบ HR ระบุ **Structure Owner = Top**
  ถ้ากล่องไม่มี Top จึงใช้คนที่ระดับสูงสุด ผู้มีสิทธิ์แก้ไขเลือกเองได้ที่แผงขวา (แผงบอกว่ามาจาก Top ระดับสูงสุด หรือเลือกเอง)
  รายชื่อในกล่องเรียง หัวหน้าหน่วย › Structure Owner Top / Middle / Lower › ระดับ และมีป้าย “Owner Top"
- **จัดคนลงกล่องอัตโนมัติ** จากชื่อหน่วยงานและสายสังกัดในระบบ HR (รวมชื่อที่สะกดต่างเล็กน้อย และสำนักผู้บริหาร CEO / COO / MD)
  หน่วยที่จับคู่ไม่ได้แก้ที่ “จับคู่หน่วยงาน” ระบบจำการจับคู่ไว้ใช้กับไฟล์เดือนถัดไป
- **Draft** ที่สร้างจาก Active ใช้กล่องเดิม คนจึงตามหน่วยเดิมไปเอง หน่วยใหม่แสดงป้าย “ใหม่” และหน่วยที่ถูกยุบแสดงรายชื่อ “คนที่ต้องจัดสรรใหม่”
- **ย้ายคนใน Draft** (ผู้มีสิทธิ์แก้ไข): ในหน้ากำลังคนของ Draft ลากชื่อจากแผงขวาไปวางบนกล่องในผัง หรือกด “ย้าย” แล้วเลือกกล่อง
  ติ๊กหลายคนเพื่อย้ายพร้อมกัน หรือเลือก “นำออกจากผัง” (ลาออก เกษียณ ย้ายบริษัท) หน้าวางแผนกำลังคนแสดง “แผนการย้ายคน” (จาก → ไป)
  แก้ ยกเลิก และ Export CSV ได้ แผนการย้ายเก็บกับ Draft นั้นในไฟล์ข้อมูลพนักงานแบบเข้ารหัส ไม่แก้ข้อมูลในระบบ HR และไม่กระทบ Active
- **รักษาการ** นำเข้าไฟล์ `Employee_workforce_Acting.xlsx` (1 แถว = 1 ตำแหน่งที่รักษาการ) ที่ช่อง “ไฟล์รักษาการ” ในหน้านำเข้า
  นำเข้าคู่กับไฟล์พนักงานหรือนำเข้าอย่างเดียวก็ได้ (ไฟล์ใหม่แทนที่รายการรักษาการเดิมทั้งหมด) เก็บเฉพาะรหัสพนักงาน หน่วยงาน ตำแหน่ง
  ระดับตำแหน่ง และวันที่เริ่มรักษาการ ระบบหาบริษัทของหน่วยที่รักษาการเอง จึงแสดงการรักษาการข้ามบริษัทได้
  - ผู้รักษาการ **นับเป็นคนเฉพาะในกล่องต้นสังกัด** ไม่นับซ้ำในกล่องที่รักษาการ
  - ผังกำลังคน: ป้ายสีส้ม “รก. ชื่อ” = ผู้รักษาการหัวหน้าหน่วย (กล่องไม่มีคนประจำ หรือระดับตำแหน่งที่รักษาการสูงกว่าหัวหน้าประจำ)
    มีตัวย่อบริษัทต้นสังกัดเมื่อข้ามบริษัท ขอบแดง = รักษาการเกิน 2 ปี ป้าย “+รก.N” = มีผู้รักษาการในกล่องที่มีหัวหน้าประจำ
  - แผงขวา: การ์ดรักษาการหัวหน้าหน่วย และรายชื่อ “รักษาการในหน่วยนี้” การ์ดพนักงานแสดงทุกตำแหน่งที่รักษาการ คลิกเพื่อไปยังกล่องนั้น (ข้ามบริษัทได้)
  - ระยะเวลา: **สีส้ม = เกิน 1 ปี ควรทบทวน** · **สีแดง = เกิน 2 ปี ควรเร่งแต่งตั้งหรือสรรหา**
  - หน้าวางแผนกำลังคน: ตาราง “ตำแหน่งที่มีผู้รักษาการ” กรองข้ามบริษัท / เกิน 1 ปี / เกิน 2 ปี / รักษาการหลายตำแหน่ง และ Export CSV
  - **แก้ไขรักษาการในระบบ**: แผงของกล่องมีปุ่ม “เพิ่มผู้รักษาการ” (ค้นหาพนักงานได้ทุกบริษัท ใส่ตำแหน่ง ระดับตำแหน่ง วันที่เริ่ม)
    และ “แก้ไข” / “ยกเลิก” ที่แต่ละคน รายการที่แก้จะติดป้าย “แก้ไขในระบบ” แยกจากไฟล์ HR (ไฟล์ HR ไม่เปลี่ยน
    การนำเข้าไฟล์รักษาการรอบใหม่ไม่ลบรายการที่แก้ไว้) ยกเลิกรายการจากไฟล์ HR แล้วคืนค่าได้ CSV มีคอลัมน์ “ที่มา”
  - หน่วยระดับบริษัทที่ไม่มีกล่องของตัวเอง ระบบลงกล่องที่ชื่อตรงกับตำแหน่งให้ (เช่น Managing Director) ที่เหลือจับคู่ได้ที่ “จับคู่หน่วยงาน”
    รักษาการในบริษัทที่ยังไม่มีผังในระบบ (เช่น CI) เก็บไว้แต่ยังไม่แสดง

### ข้อมูลพนักงานเข้ารหัส

repository นี้เป็น Public จึงเก็บรายชื่อพนักงานเป็นไฟล์เข้ารหัส `data/workforce.enc.json` เท่านั้น
(gzip + AES-256-GCM กุญแจจากรหัสผ่านด้วย PBKDF2-SHA256 600,000 รอบ) ไม่มีชื่อหรือรหัสพนักงานแบบอ่านได้ใน repository

- เปิดดูรายชื่อต้องใส่ **รหัสผ่านข้อมูลกำลังคน** ในหน้ากำลังคน ถอดรหัสในเบราว์เซอร์ ไม่ส่งรหัสผ่านไปที่ใด
  เลือก “จำไว้จนกว่าจะปิดแท็บนี้” ได้ (sessionStorage)
- รหัสผ่านแยกจาก GitHub Token: Token ใช้บันทึกไฟล์ ส่วนรหัสผ่านใช้เปิดอ่าน แจ้งรหัสผ่านเฉพาะผู้ที่ต้องใช้
  เปลี่ยนรหัสผ่านได้ที่แผงขวา (ต้องบันทึกขึ้น GitHub) ถ้าลืมรหัสผ่านต้องนำเข้าไฟล์ใหม่
- ไฟล์ Export รายชื่อ (CSV) ไม่เข้ารหัส เก็บรักษาตามนโยบาย PDPA ขององค์กร

### บันทึกพร้อมกันหลายคน

ถ้ามีคนบันทึกก่อน ระบบ **รวมการแก้ไขทีละเวอร์ชัน**: เวอร์ชันที่แก้ในเครื่องนี้ใช้ของเครื่องนี้ เวอร์ชันอื่นใช้ตาม GitHub
ถ้าไม่มีเวอร์ชันที่แก้ชนกันจะบันทึกต่อให้ทันที ถ้าชนกันจะถามก่อน (“บันทึกทับทั้งหมด” ยังมีให้เลือกแต่ไม่แนะนำ)
ข้อมูลกำลังคนใช้หลักเดียวกัน: เก็บไฟล์พนักงานและไฟล์รักษาการที่นำเข้าล่าสุด และรวมการจับคู่หน่วยงานของทั้งสองฝั่ง

## โครงสร้างข้อมูล

ทุกบริษัทและทุกเวอร์ชันอยู่ในไฟล์เดียว `data/org-structure.json` (สร้างให้อัตโนมัติเมื่อบันทึกครั้งแรก)

```jsonc
{
  "schema": 1,
  "companies": [{ "code": "PCC", "nameTh": "", "nameEn": "" }],
  "versions": [{
    "id": "v_…", "companyCode": "PCC", "versionNo": 2,
    "name": "โครงสร้างองค์กร พ.ศ. 2569",
    "status": "active",            // active | draft | inactive
    "model": "industrial",         // industrial | platform | ecosystem
    "effectiveDate": "2026-01-01", "endDate": null, "plannedDate": "",
    "approvalRef": "มติคณะกรรมการบริษัท ครั้งที่ 6/2568",
    "basedOn": "v_…",
    "root": {
      "id": "n_…", "type": "board", "name": "คณะกรรมการบริษัท",
      "nameEn": "", "code": "", "title": "", "head": "", "hc": 0,
      "staff": false, "layout": "auto", "note": "",
      "children": []
    }
  }]
}
```

`type` ของหน่วยงาน: `board` `committee` `executive` `line` (สายงาน / หน่วยธุรกิจ เช่น PEM101) `office` `platform` `division` `department` `section` `team` `position` `ai` `partner` `company` (บริษัทในเครือ เช่น `SBP (PPP 76%)`)

`style` = รูปแบบกล่องจาก Excel (`fill` `line` `lw` `text` `bold` `size` (pt) `align`), `link` = สีเส้นเชื่อมเข้าหน่วยนี้,
`box` = ตำแหน่งและขนาดกล่อง (px) เมื่อเวอร์ชันเป็น `layout: "free"`,
`hl: true` = หน่วยงานที่ไฮไลต์ (ตัวอักษรสีแดงในต้นฉบับ), `doc` ของแต่ละเวอร์ชัน = หัวกระดาษ / คำอธิบายตัวย่อ / ตารางท้ายผัง

- ตำแหน่งและขนาดกล่องตรงตามไฟล์ Excel (โหมด “จัดวางอิสระ”) รวมถึงหัวกระดาษ คำอธิบายตัวย่อ และตารางท้ายผัง

### โหมดการจัดวาง

| โหมด | การใช้งาน |

| จัดอัตโนมัติ | แอปจัดตำแหน่งให้ (กล่องขนาดเท่ากัน) ลากกล่องไปวางบนกล่องอื่นเพื่อย้ายสังกัด |

สลับโหมดได้ที่แถบเครื่องมือของ Draft เมื่อเปลี่ยนจากจัดอัตโนมัติเป็นจัดวางอิสระ กล่องจะอยู่ตำแหน่งเดิมแล้วเลื่อนต่อได้ เส้นสายบังคับบัญชาวาดใหม่ตามตำแหน่งกล่องเสมอ
- เส้นประ (dotted line) บันทึกไว้ในหมายเหตุของหน่วยงาน
- กล่องข้อความที่อยู่นอกพื้นที่พิมพ์ (PBI Job Role 2569, PEM Pre-Sale & Digital Engineering Team) และบันทึก Draft Org 1-5-69 ของ PEM เก็บไว้ในหมายเหตุเวอร์ชัน โดยไม่นำรายชื่อบุคคลเข้า
- ไฟล์ไม่มีอัตรากำลัง จึงแสดงเป็น “—” จนกว่าจะกรอก

หน่วยงานที่คัดลอกมาจากเวอร์ชันก่อนหน้าใช้ `id` เดิม ระบบจึงเปรียบเทียบได้ว่าหน่วยใดย้ายสังกัดหรือเปลี่ยนชื่อ

## รูปแบบข้อความที่ “สร้างจากข้อความ” รองรับ

```text
คณะกรรมการบริษัท
  คณะกรรมการตรวจสอบ (staff)
  กรรมการผู้จัดการ | กรรมการผู้จัดการ | | 1
    ฝ่ายขายและการตลาด | ผู้อำนวยการฝ่าย | | 2
      แผนกขายโครงการ | ผู้จัดการแผนก | | 12
    ฝ่ายทรัพยากรบุคคล
      HR Service Agent [AI]
```

- ระดับจากการเยื้องบรรทัด (Tab / เว้นวรรค) หรือเลขลำดับ `1.` `1.1` `1.1.1`
- วางจาก Excel: คอลัมน์ ระดับ | ชื่อหน่วยงาน | ประเภท | ตำแหน่งหัวหน้า | ผู้ดำรงตำแหน่ง | อัตรากำลัง
- ข้อมูลเพิ่มในบรรทัด: `ชื่อ | ตำแหน่งหัวหน้า | ผู้ดำรงตำแหน่ง | อัตรากำลัง`
- `[ฝ่าย]` `[แผนก]` `[AI]` ระบุประเภท, `(staff)` หน่วยงานขึ้นตรง หากไม่ระบุ ระบบเดาจากคำนำหน้า (ฝ่าย / แผนก / สำนัก / สายงาน …)
